# Verification scope

- **Program boundary:** Execute the exact `/app/program.kpyc` image from the complete initial `#boot` configuration (empty object memory and interpreter set, allocator at 4096, and empty runtime maps), let module initialization create its `run` binding, then call that binding with three positional arguments through the fixed semantics' `#callPython`, argument-binding, and frame machinery. The theorem stops at the C-call return boundary carrying `run`'s returned object.
- **Input domain:** `a`, `b`, and `r` range independently over every K `Int`, representing Python's unbounded exact integers. The initial value of `r` is unrestricted and is overwritten before it is read. Non-integer inputs are excluded by the source docstring.
- **Observable final state:** The returned tuple's object-reference sequence and the `stdout` and `stderr` cells. The total `isSwapResult` predicate is a definitional observation of the heap: it checks the three original integer objects and the returned tuple, returning false for every non-matching heap. The rest of the heap and interpreter bookkeeping are framed because the contract does not observe them.
- **Intended property:** If the call terminates, the returned tuple contains the original `b`, then the original `a` twice; the last two tuple positions alias the same original-`a` object. Neither output stream changes.
- **Chosen contract readings:** “State bindings” is read as the three function parameters rather than external mutable storage, because the source only rebinds locals and returns a tuple. “Return final `(a, b, r)`” is read after the assignments, hence `(b0, a0, a0)`. Verification covers partial correctness, not termination. The semantics has no concrete-run operation, so model adequacy is assessed by compilation, symbolic execution, and audit mutations rather than a concrete K run.
